# 연구 코드 바이브 코딩 가이드

도구는 자유입니다(ChatGPT·Claude·Gemini 웹, Colab 내장 AI, Claude Code·Codex·Cursor 같은 에이전트형 도구).
도구가 달라도 **결과를 믿을 수 있게 만드는 방법**은 같습니다.

## 0. 에이전트가 코드를 다 써 줄 때, 무엇을 배우나

에이전트(Claude Code, Codex, Colab MCP 등)는 사양이 분명하고 자동 체크가 있는 문제를 빠르게 풉니다.
그래서 이 과정은 코드를 쓰는 능력이 아니라 **AI의 결과를 믿어도 되는지 판단하는 능력**을 연습합니다.

| 기록 | 언제 | 왜 |
|---|---|---|
| 🔮 예측 | 실행 **전** | 결과를 보고 그럴듯하게 설명하는 것은 쉽습니다. 미리 적은 예측이 틀린 지점이 배움이 일어나는 곳입니다 |
| 🧾 검증 기록 | 체크 통과 **후** | ✅가 '맞는 이유'로 나왔는지, 우연히 통과했는지 근거를 적습니다 |

Day 2는 일부러 **테스트를 먼저** 만들고, 정답 비교는 마지막에 한 번만 합니다. 실제 연구에는 `check`가 없기 때문입니다.

## 1. 이 과정의 다섯 가지 원칙

1. **계약서를 먼저 준다.** `docs/01_contract.md`를 컨텍스트로 넣고 "이 문서에 없는 규칙은 만들지 말고 모른다고 답하라"고 요청합니다.
2. **돌아간다 ≠ 맞다.** 에러 없이 실행되는 코드가 가장 위험합니다. 차원·순서·좌표계는 숫자로 확인합니다.
3. **추측 대신 테스트.** "왜 넘어지지?"가 아니라 "이 불변식을 검사하는 테스트를 먼저 짜 줘"라고 요청합니다.
4. **기준 실험으로 원인을 분리한다.** 공식 샘플·공식 조건에서 먼저 확인하고, 그다음 내 데이터·내 변경을 넣습니다.
5. **프롬프트와 판단을 기록한다.** `templates/prompt_log.md`에 요청·AI 답·내가 확인한 근거를 남깁니다.

## 2. 프롬프트 템플릿

**구현 요청**
```
[컨텍스트] 첨부한 계약서(01_contract.md)와 아래 함수 시그니처를 기준으로 한다.
[목표] <미션 목표 한 줄>
[입력/출력] <shape, 순서, 단위>
[제약] 계약서에 없는 규칙을 추가하지 말 것. 불확실한 부분은 코드 주석에 TODO(확인 필요)로 표시.
[검증] 구현과 함께, 이 함수가 맞는지 확인할 assert 3개를 같이 작성.
```

**디버깅 요청**
```
아래는 실행 결과와 체크 메시지다. 원인을 바로 고치지 말고,
(1) 가능한 원인 후보를 계약서 조항과 연결해 나열하고
(2) 후보를 하나씩 가려낼 수 있는 최소 테스트를 작성해 줘.
테스트 결과를 보고 내가 다음 단계를 지시하겠다.
```

**리뷰 요청**
```
이 함수가 계약서 3~5절과 일치하는지 줄 단위로 대조표를 만들어 줘.
일치/불일치/계약서에 없음 세 가지로만 표시.
```

## 3. 실제 사례 — 이 교육자료가 만들어진 과정 (01→08)

이 저장소는 실제 연구 대화(Codex/ChatGPT)로 만든 노트북 8개를 바탕으로 했습니다. 각 노트북 첫 셀에 사용자 원문 요청이 남아 있습니다.

| # | 사용자 요청(요약) | 결과 | 배울 점 |
|---|---|---|---|
| 01 | "코랩으로 gear-sonic 어디까지 사용 가능한지" | ONNX 입출력·CPU 추론 확인 | 범위부터 확인하는 질문 |
| 02 | "바로 실행 가능하게 작성" | T4 추론, MuJoCo 미리보기 | 실제 실행 로그로 OSMesa 오류 수정 |
| 03 | "그럼 그렇게 코랩에 작성해봐" | 인체 동작 → 64차원 토큰 | 근사 변환임을 명시 |
| 04 | "decoder까지 연결해서 G1 모션까지" | 29관절 출력 + 영상 | 영상이 나와도 검증은 아님 |
| 05 | "제대로 된 순서와 좌표계로 들어가는지 확인" | 이력 순서·기본각 오프셋 수정 | **사람의 의심**이 버그를 찾음 |
| 06 | "공식 샘플 하나로 문제없는지부터" | 공식 데이터로 기준 실험 | 원인 분리. 그런데 여기서도 쿼터니언 순서 버그가 숨어 있었음 |
| 07 | "로컬 코드 확인해서 수정" | 쿼터니언 xyzw 확인, 공식 PD 토크 모델 → 완주 | 공식 구현과 대조 |
| 08 | "코랩에서 MuJoCo 메쉬 영상으로" | 렌더링 전용 노트북 | 계산과 시각화 분리 |

Day 2의 버그 사냥에 넣은 버그는 모두 이 과정에서 실제로 나왔던 유형입니다.
